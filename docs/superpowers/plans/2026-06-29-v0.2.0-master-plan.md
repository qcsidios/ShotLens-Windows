# ShotLens Windows v0.2.0 总实施计划

> **供智能开发代理使用：** 每个阶段开始前必须单独编写一份 Superpowers 细粒度实施计划。本路线图只定义阶段边界，不可代替当前阶段的实施计划直接执行。

**目标：** 从零重建 ShotLens Windows v0.2.0；所有改动都能追溯到已确认需求、详细技术规格、自动化测试、Windows 实机证据和应用内覆盖升级结果。

**需求基线：** `REQUIREMENTS.md`

**详细技术规格：** `docs/superpowers/specs/2026-06-29-shotlens-windows-v0.2.0-design.md`

## 一、计划规则

1. 同一时间只实施一个阶段。
2. 每个阶段在 `docs/superpowers/plans/` 下建立独立计划。
3. 阶段计划必须写明准确文件、失败测试、验证命令、预期输出、提交节点和 Windows 实机检查。
4. 编译通过不等于阶段完成。
5. Windows 专属能力必须有 Windows 实机证据。
6. 每个验收失败项必须先形成自动化回归测试或可重复的人工复现步骤，再修复。
7. 推送、Tag、Pre-release 和正式 Release 都要在执行前获得明确授权。
8. 后续计划必须使用前序阶段产出的技术决策，禁止提前猜测。
9. 所有说明文档使用中文；代码标识符、命令、路径和协议字段保留英文。

## 二、阶段 0：基础设施与技术可行性

**详细计划：** `docs/superpowers/plans/2026-06-29-stage-0-foundation-validation.md`

**粒度：** 18 个任务、185 个检查项（含阶段完成门槛）。

### 交付物

- 全新解决方案与依赖边界。
- 支持 beta 的语义化版本。
- 稳定版与 beta 更新选择逻辑。
- 安全下载安装器并启动覆盖升级。
- 最小更新诊断界面。
- 稳定版与 beta 双身份 Inno Setup 安装器。
- GitHub Pre-release 工作流。
- 物理像素与 DPI 坐标模型。
- DXGI 按显示器截图原型。
- OCR 独立进程协议。
- OCR 基准集与评分器。
- ONNX 与 PaddleSharp 两条候选路线。
- 有数据支撑的 OCR 选型结论。
- 稳定版与 beta 并行安装，以及 `beta.1 → beta.2` 应用内升级。

### 阶段出口

- 阶段 0 的全部完成门槛通过。
- OCR 选型结论已记录。
- 用户 Windows 电脑上的 DXGI 诊断通过。
- beta 覆盖升级保留设置，且不影响稳定版。

# OCR beta 漏识别回归收录规范

> 状态：阶段 0 已建立，beta 阶段执行

## 一、基本原则

- 默认不收集、不上传用户截图。
- 只有用户主动提交并明确同意用于修复 OCR 时才处理。
- 原始截图只用于脱敏和复现，完成后删除。
- 回归仓库只保存最小必要裁剪、脱敏图片和技术标注。
- 生成基准用于公平选型，不代表完整真实用户场景；beta 回归用于补充真实失败类型。

## 二、禁止收录

出现以下内容且无法可靠遮挡时，不得收录：

- API Key、密码、验证码、Cookie、访问令牌。
- 身份证件、银行卡、医疗记录或精确住址。
- 私聊、邮件正文、未公开商业数据。
- 可识别个人的头像、姓名、电话或账号。
- 用户没有权利提供的第三方内容。

## 三、脱敏步骤

1. 复制原图到隔离临时目录，不直接修改用户原件。
2. 只裁剪导致漏识别的最小区域。
3. 使用不可逆纯色块覆盖敏感文字和图像，不使用模糊或马赛克。
4. 删除文件名、EXIF、路径、窗口标题和其他来源元数据。
5. 重新导出 PNG，并人工放大检查遮挡边缘。
6. 计算 SHA-256，确认仓库中不存在重复样本。
7. 删除隔离目录中的原始截图。

## 四、标注字段

每个回归样本至少记录：

- 匿名样本 ID。
- 图片 SHA-256。
- 语言、主题、DPI、最小字高和布局类型。
- 期望文字与阅读顺序。
- 失败引擎、引擎版本和模型版本。
- 失败类型：整段漏识别、漏行、错字、错序、坐标错误或性能超限。
- 脱敏检查人和检查日期。
- `containsSensitiveData: false`。

不得记录用户姓名、联系方式、原始文件名或来源网址。

## 五、进入自动回归的门槛

- 图片和标注通过数据集校验器。
- ONNX 与 PaddleSharp 候选读取到相同 SHA-256。
- 样本能稳定复现至少两次。
- 修复后保留该样本，防止后续版本回退。
- 整段漏识别必须单独列入中文报告，不得只被平均准确率掩盖。
